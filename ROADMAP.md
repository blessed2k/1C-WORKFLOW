# ROADMAP

Что уже работает — таблица инструментов в `README.md` и `docs/tools-index.md`. Здесь только
открытые направления; порядок не означает приоритет.

## Индексный слой

- **FTS5 для `search_code`.** Таблица `fts_symbols` уже есть в схеме `internal/store`, но ни
  один инструмент её не использует: `search_code` по-прежнему читает выгрузку напрямую
  (`internal/source`).
- **Перевод старых инструментов на индекс.** Легаси-слой (`internal/source`) и индексный слой
  сосуществуют намеренно; перевод идёт по инструменту за раз, без поломки контрактов
  (`cmd/mcp1c/tools_contract_test.go`).
- **Рёбра `find_impact`.** Не собираются виды `dependency_edge` `subsystem-contains`,
  `exchange-plan-contains`, `epf-uses-object`, а `reference.target_object_id` не заполняется.
  Ограничения названы в описании инструмента.
- **Инкрементальный reindex на крупных конфигурациях.** На ~50 тыс. файлов инкремент упирается в
  лимит SQL-переменных SQLite (`ObjectDataEdgesDependingOnFiles`).
- **Бюджеты производительности.** Холодный полный индекс крупной конфигурации пока не укладывается
  в бюджет, см. `docs/benchmarks.md`.
- **Семантический поиск (embeddings)** в первую версию не входит.

## Расширения

- **`extension_compat`** — что сломает обновление типовой: расширение плюс старая и новая
  выгрузка конфигурации → перехваченные методы, которые исчезли или сменили сигнатуру,
  заимствованные реквизиты, которых больше нет, оригиналы методов под `&Вместо`, которые
  изменились.
- **`interceptor_conflicts`** — один метод перехвачен несколькими расширениями (`&Вместо` +
  `&Вместо`, несколько `&После` с неопределённым порядком) по всем методам, а не только по
  формам, как `form_impact`.

## Доработки существующих инструментов

- `bsp_extension_points`: механизмы БСП помимо переопределяемых модулей (подключаемые команды,
  дополнительные реквизиты), фильтр точек по объекту, один парсер экспортных методов вместо двух.
- `get_movements review=true`: контроль остатков после записи движений, проверка
  `РежимПроведения`.
- `exchange_audit`: регистрация из произвольного кода, правила регистрации ППД, XDTO-формат.
- `new_object_checklist`: не засчитывать планы обмена, в состав которых входит почти вся
  конфигурация (порог по самой выгрузке, без зашитых имён); управление доступом БСП; правила
  конвертации универсального формата; колонки журналов документов.
- `visibility_audit`: значения функциональных опций из живой базы, параметризованные опции.
- `write_path`: перехватчики расширений на обработчиках подписок, путь удаления
  (`ПередУдалением`).
- `rights_audit`: значения RLS-шаблонов БСП, права на реквизиты и табличные части.
- `find_dependency_paths`: формы, подписки, журналы документов, упоминания в коде.
- `find_metadata_usages`: разбор MXL-макетов, точное поле схемы компоновки.
- `query_advisor`: соединение по составному типу, `ИНДЕКСИРОВАТЬ ПО` временных таблиц,
  `ОБЪЕДИНИТЬ` вместо `ОБЪЕДИНИТЬ ВСЕ`.
- Кэш выгрузки: тела общих модулей.
- **`find_objects_by_summary`** — поиск объекта по описанию на естественном языке.

## Live-режим

- Live `/form` и русификация типов в live `/object` под формат offline.
- Сквозная обкатка HTTP-коннектора на тестовой базе.

## Не делать

- `bsl_lint` — дубль bsl-language-server, который подключается отдельным MCP-сервером.
  Проверку написанного BSL по конфигурации закрывает `validate_bsl`.
- Семантический поиск по коду и память проекта — это задача отдельных инструментов (например,
  Serena).
- Прогон YAxUnit и другие проверки, требующие рантайма 1С: платформа не везде запускается
  headless.
- `Sampling` / `Roots` / `Logging` MCP — устаревают (SEP-2577), новое на них не строится.
