# Безопасность

## Как сообщить об уязвимости

Не публикуйте сведения об уязвимости в открытых issues. Сообщите о ней приватно через
GitHub Security Advisories: вкладка **Security** репозитория, кнопка
**Report a vulnerability**
([прямая ссылка](https://github.com/blessed2k/1C-WORKFLOW/security/advisories/new)).

Опишите версию (`mcp1c --version`), ОС, режим работы (offline, индекс, live), шаги
воспроизведения и возможные последствия. Исправления выпускаются для последней версии.

## Модель безопасности

- **Сервер только читает.** Инструменты не меняют ни файлы выгрузки, ни базу. Пишет сервер
  только собственное состояние: реестр проектов и файлы индекса в
  `<projects-root>/.mcp1c/`.
- **Коннектор живой базы только читает.** HTTP-сервис расширения отдаёт метаданные, журнал
  регистрации, предопределённые элементы и результаты запросов. `/query` выполняет только
  текст, начинающийся со слова `ВЫБРАТЬ`/`SELECT`, остальное получает HTTP 403, и та же
  проверка повторяется на стороне сервера. `Выполнить()` и `Вычислить()` к входным данным
  не применяются, привилегированный режим не включается.
- **Права определяет база.** Запросы коннектора выполняются от имени пользователя,
  прошедшего HTTP-аутентификацию, с его ролями и ограничениями на уровне записей. Используйте
  отдельного пользователя с минимальными правами на чтение и тестовые копии баз.
- **Учётные данные.** Пароль передавайте через переменную окружения `MCP_1C_PASSWORD`;
  файл `--bases` хранит пароли открытым текстом, держите его вне репозиториев и с правами
  только для своего пользователя. Сервер не возвращает пароли в ответах.
- **Пути.** Файлы компонентов проекта читаются только внутри корня компонента.
- **Карта графа** (`mcp1c graph`) слушает только `127.0.0.1`.
- **Транспорт MCP** локальный (stdio), сетевого MCP-сервера нет.
