# ADR-4. Единая точка чтения XML для классификации компонентов (D01)

## Контекст

Таск 06 должен был стать единственной точкой разбора XML метаданных
(`internal/parse/meta`) — критерий приёмки требовал «ни одного нового места
чтения XML вне этого пакета». Но таск 02 (`internal/workspace/kind.go`),
написанный раньше, чем `parse/meta` вообще существовал, уже содержал
собственный узкий потоковый разбор через `encoding/xml` двух
полей-дискриминаторов (`Object`, `ConfigurationExtensionPurpose`) — он был
нужен, чтобы классифицировать каталог компонента (конфигурация/расширение) до
того, как индексация вообще стартует.

## Решение

`internal/parse/meta` получает экспортную функцию классификации корня по
сырым байтам; `internal/workspace/kind.go` вызывает её вместо собственного
`xml.Decoder`. `encoding/xml` убран из `workspace` полностью.

## Почему

Оставить `kind.go` как «достаточно узкий разбор, чтобы не считаться
нарушением» не рассматривалось всерьёз: по факту это второй парсер XML одной
и той же сущности, что прямо запрещено §6 архитектуры и собственным
критерием таска 06. Найдено независимой проверкой Codex — не поймано ни
гардом `internal/arch` (он проверяет только импорт-граф, не паттерны
использования пакетов), ни двумя предыдущими раундами ревью. То, что
нарушение прошло мимо штатного процесса дважды, важнее самого фикса.

## Последствия

Единая точка чтения XML восстановлена, но гард `internal/arch` по-прежнему
не умеет ловить *будущее* появление второго парсера по паттерну импорта
(`encoding/xml` вне `parse/meta`, второй токенайзер запроса вне
`parse/query`) — это отдельно зафиксировано как незакрытый долг таска 16 в
манифесте. Классификация компонента в `workspace` теперь зависит от
`parse/meta`, что связывает эти два пакета раньше по времени, чем
предполагала исходная нарезка тасков.
