# ADR-4. Единая точка чтения XML для классификации компонентов

## Контекст

`internal/parse/meta` задуман как единственная точка разбора XML метаданных:
нового чтения XML вне этого пакета быть не должно. Но `internal/workspace/kind.go`,
написанный раньше, чем появился `parse/meta`, содержал собственный узкий
потоковый разбор через `encoding/xml` двух полей-дискриминаторов (`Object`,
`ConfigurationExtensionPurpose`). Он нужен, чтобы классифицировать каталог
компонента (конфигурация или расширение) до старта индексации.

## Решение

`internal/parse/meta` получает экспортную функцию классификации корня по
сырым байтам; `internal/workspace/kind.go` вызывает её вместо собственного
`xml.Decoder`. `encoding/xml` убран из `workspace` полностью.

## Почему

Оставить `kind.go` как «достаточно узкий разбор, чтобы не считаться
нарушением», не рассматривалось: по факту это второй парсер XML одной и той
же сущности, что прямо запрещено §6 архитектуры. Гард `internal/arch` это
нарушение не ловит: он проверяет только импорт-граф, а не паттерны
использования пакетов. Нарушение нашлось только независимой проверкой кода.

## Последствия

Единая точка чтения XML восстановлена, но гард `internal/arch` по-прежнему
не умеет ловить *будущее* появление второго парсера по паттерну импорта
(`encoding/xml` вне `parse/meta`, второй токенайзер запроса вне
`parse/query`): это открытый долг. Классификация компонента в `workspace`
теперь зависит от `parse/meta`, то есть эти два пакета связаны раньше, чем
предполагала исходная раскладка по слоям.
