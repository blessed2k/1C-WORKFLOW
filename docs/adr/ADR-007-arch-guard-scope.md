# ADR-7. Гард `internal/arch` включает `internal/index` в запрещённые импорты `cmd`

## Контекст

Правило «`cmd` ходит в индекс только через `app`»: единственная точка входа в
`internal/index` идёт через фасад `internal/app`, и это должно
гарантироваться автоматически гардом `internal/arch`, а не только
код-ревью.

## Решение

`запрещеноВCmd` (список запрещённых импортов в `internal/arch/rules.go`) не
включал `internal/index`: гард не поймал бы прямой импорт `internal/index` из
`cmd/mcp1c`. Пакет добавлен в список.

## Почему

Полагаться на код-ревью каждого следующего изменения вместо автоматической
проверки не рассматривалось: это тот же класс риска, что и в ADR-004. Гард
уже один раз пропустил похожее нарушение границы (второй XML-парсер) именно
потому, что список правил был неполным. Точечное расширение списка дешевле,
чем повторный пропуск в коде, где `internal/index` активно используется.

## Последствия

Гард теперь ловит прямой импорт `internal/index` из `cmd/mcp1c`, но
остаётся тем же классом решения, что и раньше: он проверяет конкретный
список запрещённых импортов, а не общий паттерн «доступ к слою мимо
фасада». Каждая новая граница модуля требует отдельной записи в этот список
вручную, иначе для следующего модуля повторится тот же пробел.
