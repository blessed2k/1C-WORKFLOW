# Фаза 0A: storage spike и ADR-2 — итоговый отчёт

- **Дата:** 17.08.2026.
- **Прогон, из которого взяты все числа:** `run_id = 20260816T203836Z-76659`,
  `harness_hash = 8657555781fa65d9`, `harness_vcs = a97150897005+dirty`.
- **Статус ADR-2:** ACCEPTED. macOS — runtime validated. Windows — compile
  validated, runtime validation отложена.
- **Статус фазы:** 0A закрыта, ожидает финального ревью. Фаза 0B и
  `internal/store` не начинались.
- **Источник архитектурной истины:** `docs/architecture-index.md` (ACCEPTED).
  Бюджеты раздела 28 фазой 0A **не пересматривались и не ослаблялись**.

## 1. Принятое решение

| Элемент | Решение |
|---|---|
| Драйвер | `modernc.org/sqlite` |
| API | `database/sql` |
| Сборка production | `CGO_ENABLED=0` |
| Публикация эпох | двухслотовый checksummed pointer |

`zombiezen.com/go/sqlite` и `github.com/mattn/go-sqlite3` выведены из
кандидатов production и остаются в spike как benchmark/reference: вторая точка
отсчёта на замерах и независимая проверка того, что поведение движка не зависит
от обёртки.

### Платформенная стратегия

macOS и Windows — равноправные целевые платформы. macOS не является основной
платформой продукта: сейчас это единственная доступная среда runtime-тестирования.

| Платформа | Статус | Чем подтверждён |
|---|---|---|
| macOS (darwin/arm64) | runtime validated | полный прогон, тесты, race, сверка |
| Windows (windows/amd64, arm64) | compile validated | кросс-сборка `CGO_ENABLED=0` |
| Linux (linux/amd64) | compile validated | кросс-сборка, целевой не является |

Отсутствие Windows runtime-прогона не блокирует 0B. Правила общего кода
(раздел 13.1 ADR): `CGO_ENABLED=0` в production; platform-specific код только
за build tags; пути и файловые операции только через `path/filepath`, `os`,
`io/fs`; Unix-only предположения в общем коде запрещены; Windows cross-build на
каждом этапе.

## 2. Что сделано в этой итерации

### 2.1 Жизненный цикл PRAGMA разделён по-настоящему

`Candidate` получил два конструктора вместо одного:

| Конструктор | Что применяет | Где используется |
|---|---|---|
| `Create` | creation-only → persistent → per-connection | создание базы и новой эпохи |
| `Open` | только per-connection + проверка фактических persistent | читатели, писатель, пул |

Три класса разведены и не могут снова слиться: `auto_vacuum` выполняется до
любого DDL на пустой БД, `journal_mode=WAL` записывается один раз и при каждом
открытии **проверяется чтением** (несовпадение — ошибка открытия), остальные
живут ровно на своём соединении. Пул читателей не переустанавливает ни
`auto_vacuum`, ни `journal_mode`.

Разделение сразу себя оправдало: базы, создававшиеся в тестах через `Open`,
стали получать `journal_mode=delete`, и проверка это поймала.

Тесты: `TestPragmaClassesAreDisjointAndOrdered`, `TestCreatePragmaOrder`,
`TestOpenPragmaListHasNoCreationOrPersistent`,
`TestReopenKeepsPersistentAndAppliesConnection`,
`TestPragmaOrderDecidesAutoVacuum`.

### 2.2 Испорченное соединение читателя уничтожается и заменяется

| Свойство | Решение |
|---|---|
| размер по умолчанию | 4, настраивается; 0 означает «взять умолчание», а не «без границы» |
| ожидание соединения | прерывается контекстом и закрытием пула |
| прерванное или испорченное соединение | `Discard`: закрывается и **заменяется** новым |
| неудачная замена | пул сужается, это видно в `Stats` (`ReplaceFailed`) |
| закрытие пула | закрывает только свободные; арендованные закрывает `Release` |

Тесты: `TestReaderPoolIsBounded`, `TestReaderPoolWaitIsContextAware`,
`TestReaderPoolCloseWakesWaiters`, `TestReaderPoolClosed`,
`TestReaderPoolNeverHandsOutClosedConn`, `TestReaderPoolCloseDoesNotKillLeasedConn`,
`TestReaderPoolClosesEveryConnection`, `TestReaderPoolCancellationDiscardsAndReplaces`.
Последний проходит цепочку отмена → выброс → замена → рабочий `SELECT 1`.

### 2.3 Windows-гейт: один непротиворечивый список

- Единственный список — таблица раздела 13.2 ADR; скрипт на неё ссылается и не
  дублирует. Дубли пунктов 8-10, оставшиеся от прежней редакции, устранены:
  теперь это сквозной список из четырнадцати строк без повторов.
- Без `MCP1C_SPIKE_DUMP` скрипт выходит с кодом 2: acceptance-прогон идёт

- Синтетика доступна только явным `-SmokeOnly`, с предупреждением о
  непригодности для приёмки; отчёт с `corpus_kind = synthetic` сверка отвергает

- `wmic` удалён: сведения о машине берутся из реестра (`RegGetValueW`) и Win32

- Добавлена эксклюзивная блокировка `results\.run.lock` с PID владельца и
  снятием в `finally`.

### 2.4 Генератор ADR молча съедал разделы

Замена генерируемого раздела искала его конец как «следующий `###`, а если
такого нет — следующий `##`». После последнего генерируемого подраздела
ближайшим `###` оказывался 6.1, и всё между ними — разделы 5 и 6 целиком —
уходило в замену. Дефект сработал дважды, оба раза бесшумно: сверка проверяет
числа в таблицах, а исчезнувшая прозаическая рекомендация числом не является.

Исправлено: конец раздела — ближайший следующий заголовок **любого** уровня.
Тест `TestUpdateADRKeepsEveryHeading` сверяет список заголовков до и после
генерации; на старой логике он падает (33 заголовка против 31).

### 2.5 Сравнительная серия AB/BA снята с доказательной базы

Серия запускалась дважды. Первый заход был вытеснен вторым, а второй шёл
параллельно с `go test -race` — то есть ровно в тех условиях, которые ADR сам
объявляет негодными для замера. Его числа первый заход не воспроизводят.

Раздел ADR, опиравшийся на серию, удалён вместе с генерирующим его кодом;
испорченный артефакт удалён, чтобы его нельзя было прочитать как валидный.
Инструмент `cmd/abseries` сохранён для будущих справочных замеров на свободной
машине. Ограничение и методический урок записаны в раздел 12 ADR.

На решение это не влияет: реализация выбрана по качественным основаниям, а
разброс `modernc` принят мейнтейнером как риск, не ослабляющий бюджет.

### 2.6 Кроссплатформенность общего кода

Проверено и исправлено:

- `syscall` и `golang.org/x/sys` встречаются только в файлах за build tags
  (`machine_windows.go`, `rss_windows.go`, `rss_unix.go`, `rss_child_unix.go`,
  `machine_darwin.go`, `machine_linux.go`); в общем коде их нет.
- Ветвлений по `runtime.GOOS` в логике нет: единственные обращения — запись
  `GOOS` в отчёт и обёртка `runtimeGOOS()` для тестов.
- Хардкода разделителя пути нет; найденные `"/"` — разделитель в именах
  Go-бенчмарков, а не путь.
- **Найден пробел:** `CollectMachineInfo` существовал только для darwin, linux
  и windows, из-за чего сборка под любой другой GOOS падала на общем файле
  `report.go`, а не на платформенном. Добавлен `machine_other.go` с тегом
  `!darwin && !linux && !windows`. Проверено: `GOOS=freebsd` теперь собирается.

### 2.7 Сверка ADR с источником истины

Прямое сличение с `docs/architecture-index.md` дало три расхождения, все
исправлены в ADR (новый раздел 14.1 — реестр отходов).

1. **Бюджет размера индекса был прочитан наполовину.** Раздел 28 индекса задаёт
   его двумя условиями: относительным (кратность объёму BSL+XML) и абсолютным
   («сотни МБ, не ГБ»). ADR нёс только абсолютное и объявлял бюджет
   невыдержанным. Относительное условие на этом корпусе **выдержано** (1.58x).
   Теперь в таблице 4.7 обе строки, и вердикт по каждой свой. Вердикты и в
   таблице, и в прозе вычисляются из чисел: первая правка вписала их в шаблон
   («одно выдержано, другое нет»), что верно ровно для этого прогона и на
   следующем разошлось бы с таблицей строкой выше. Закрыто функцией `sizeNote`
   и тестом `TestSizeNoteFollowsTheNumbers`, который читает готовую фразу и
   падает на прошитом варианте.

   Дальше пришлось развести два требования, которые тянут в разные стороны.
   Вердикт по сырому числу давал строку «2.00x — выдержано»: числа верны, рядом
   читаются как ошибка. Вердикт по округлённому числу убирал эту строку, но
   **ужесточал бюджет**: кратность 1.996 бюджет раздела 28 выдерживает, а
   документ объявлял бы её невыдержанной из-за формата вывода. Итог: порог
   применяется к настоящему числу (иначе ADR молча меняет критерий, чего он
   делать не вправе), а печатается число с той точностью, при которой оно лежит
   по ту же сторону порога — 1.996 выводится как `1.996x`, обычные значения
   формат не меняют. Совпадение с порогом точностью не лечится: значение
   действительно равно границе. Закрыто `sizeVerdicts` + `fmtVsThreshold` и
   тестом `TestSizeVerdictsFollowTrueValueAndPrintUnambiguously`, который
   проверяет оба требования сразу и падает на каждом из двух вариантов.
2. **Раздел 4.7 смягчал перерасход cold build «разбросом между заходами»** —
   тем самым аргументом, который этой же итерацией снят с доказательной базы
   вместе с серией. Формулировка убрана из генератора: перерасход называется
   числом, а величина разброса объявляется неизмеренной.
3. **Два отхода от раздела 11 индекса не были названы отходами.** Индекс пишет
   «читатели без ограничений» — ADR вводит ограниченный пул; индекс пишет
   `_txlock=immediate` в DSN — ADR использует явный `BEGIN IMMEDIATE`. Оба
   теперь зафиксированы как отходы с причиной, и оба оставлены на решение
   мейнтейнера: правку индекса ADR делать не вправе.

Там же — сверка с DoD фазы 0A: восемь пунктов закрыты, два (поведение эпох на
Windows и атомарность replace указателя **на Windows**) не закрыты и отложены
решением о платформенной стратегии.

### 2.8 Прочее

- В отчёт добавлены сведения о машине (`machine`) — гейт требует их заполнения.
- `corpus_bsl_files` фиксируется в JSON; `.bsl` и `.xml` отбираются в пропорции
  масштаба, `.bsl` идут первым непрерывным диапазоном, поэтому «инкремент
  одного BSL-файла» действительно берёт BSL-файл.
- Нумерация раздела 12 ADR выправлена: было три коллизии номеров
  (два «3a», два «4»), стало 1-13 без повторов.

Бюджет §28 на размер индекса состоит из двух условий: относительное
(< 2x объёма BSL+XML) выдержано, абсолютное («сотни МБ, не ГБ») — нет. Ранняя
редакция ADR несла только абсолютное условие, из-за чего вердикт был строже
источника истины; исправлено.

Три невыдержанных бюджета приняты как **risk signal**. Сами цели сохраняются:
targeted reconciliation — обязательное требование фазы 3, решение о
материализации `call_edge` отложено до фаз 5-6, путь к cold build лежит через
фазу вставки ссылок, а не через смену драйвера.

Оговорка, без которой числа читаются строже, чем следует: счётчики фактов
смоделированы, а affected set инкремента раздут коллизиями синтетических ключей
(раздел 12 ADR), то есть цена инкремента здесь **завышена**.

## 5. Что НЕ проверено

1. **Windows runtime.** Прогон не выполнялся: рабочего Windows-ПК нет. На macOS
   нельзя проверить даже синтаксис PowerShell — `pwsh` не установлен. Заявляется
   compile validated, не более.
2. **Счётчики фактов смоделированы**, а не получены парсером.
3. **Affected set раздут** коллизиями синтетических ключей.
4. **Одна машина, одна ОС, один диск** (APFS).
5. **Одна выгрузка** — демо-база УТ.
6. **Пул читателей не мерился под нагрузкой полного объёма**: его свойства
   проверены тестами, но прогоны раздела 4.5 ADR идут без аренды.
7. **Файловый кеш ОС не контролировался**, поэтому слово «холодный старт» к
   числам не применяется.
8. **Контролируемого сравнения реализаций по скорости нет** — см. 2.5.

2. **Коммит выполнен** (17.08.2026): изменения фазы 0A лежат в `a971508`
   («фаза 0A — storage spike и ADR-2 по драйверу SQLite») и `1a7897b`

   Не запушено — push отдельным разрешением.
3. **Windows-прогон**, когда появится рабочий ПК, по таблице раздела 13.2 ADR:

   ```powershell

   powershell -ExecutionPolicy Bypass -File .\scripts\run-windows.ps1
   ```

   После него статус платформы меняется на runtime validated.
