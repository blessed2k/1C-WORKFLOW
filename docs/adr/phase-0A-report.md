- **Дата:** 17.08.2026.
- **Замер, из которого взяты все числа:** `run_id = 20260816T203836Z-76659`,
  `harness_hash = 8657555781fa65d9`, `harness_vcs = a97150897005+dirty`.
- **Статус ADR-2:** ACCEPTED. macOS: runtime validated. Windows: compile

- **Источник архитектурной истины:** `docs/architecture-index.md`.
  Бюджеты раздела 28 фазой 0A **не пересматривались и не ослаблялись**.

Полное обоснование, методика и все таблицы замеров живут в

## 1. Принятое решение

| Элемент | Решение |
|---|---|
| Драйвер | `modernc.org/sqlite` |
| API | `database/sql` |
| Сборка production | `CGO_ENABLED=0` |
| Публикация эпох | двухслотовый checksummed pointer |

`zombiezen.com/go/sqlite` и `github.com/mattn/go-sqlite3` выведены из
кандидатов production и остались в spike как benchmark/reference: вторая точка
отсчёта на замерах и независимая проверка того, что поведение движка не зависит
от обёртки.

### Платформенная стратегия

macOS и Windows — равноправные целевые платформы. macOS не является основной
платформой продукта: сейчас это единственная доступная среда runtime-тестирования.

| Платформа | Статус | Чем подтверждён |
|---|---|---|
| macOS (darwin/arm64) | runtime validated | полный прогон, тесты, race, сверка |
| Windows (windows/amd64, arm64) | compile validated | кросс-сборка `CGO_ENABLED=0` |
| Linux (linux/amd64) | compile validated | кросс-сборка, целевой не является |

Отсутствие Windows runtime-прогона не блокирует 0B. Правила общего кода
(раздел 13.1 ADR): `CGO_ENABLED=0` в production; platform-specific код только
за build tags; пути и файловые операции только через `path/filepath`, `os`,
`io/fs`; Unix-only предположения в общем коде запрещены; Windows cross-build на
каждом этапе.

## 2. Технические находки по оснастке spike

### 2.1 Жизненный цикл PRAGMA

Два конструктора вместо одного: `Create` (creation-only, затем persistent, затем
per-connection; создание базы и новой эпохи) и `Open` (только per-connection плюс
проверка фактических persistent; читатели, писатель, пул). `auto_vacuum` выполняется до
любого DDL на пустой БД, `journal_mode=WAL` записывается один раз и при каждом открытии
**проверяется чтением** (несовпадение: ошибка открытия). Проверка сразу поймала базы,
которые тесты создавали через `Open`: они получали `journal_mode=delete`.

### 2.2 Испорченное соединение читателя уничтожается и заменяется

| Свойство | Решение |
|---|---|
| размер по умолчанию | 4, настраивается; 0 означает «взять умолчание», а не «без границы» |
| ожидание соединения | прерывается контекстом и закрытием пула |
| прерванное или испорченное соединение | `Discard`: закрывается и **заменяется** новым |
| неудачная замена | пул сужается, это видно в `Stats` (`ReplaceFailed`) |
| закрытие пула | закрывает только свободные; арендованные закрывает `Release` |

### 2.3 Генератор таблиц ADR молча съедал разделы

Конец генерируемого раздела искался как «следующий `###`, а если такого нет, следующий
`##`». После последнего генерируемого подраздела ближайшим `###` оказывался 6.1, и
разделы 5 и 6 целиком уходили в замену. Дефект сработал дважды и бесшумно: сверка
проверяет числа, а исчезнувшая проза числом не является. Исправление: конец раздела
определяется ближайшим следующим заголовком **любого** уровня; тест сверял список
заголовков до и после генерации (на старой логике 33 заголовка против 31).

### 2.4 Вердикт по бюджету размера вычисляется из чисел

Бюджет размера индекса (раздел 28) задан двумя условиями: относительным (кратность
объёму BSL+XML) и абсолютным («сотни МБ, не ГБ»). Вердикт по каждому вычисляется, а не
вписан в шаблон. Порог применяется к настоящему числу, а печатается оно с точностью, при
которой лежит по ту же сторону порога: 1.996 выводится как `1.996x`, а не «2.00x,
выдержано». Иначе формат вывода либо давал противоречивую строку, либо ужесточал бюджет.

### 2.5 Сравнительная серия AB/BA снята с доказательной базы

Второй заход серии шёл параллельно с `go test -race`, то есть в условиях, которые ADR
объявляет негодными для замера, и первый заход он не воспроизвёл. Артефакт удалён,
раздел ADR, опиравшийся на серию, тоже. Инструмент серии был одноразовым и в репозиторий
не вошёл. На решение это не влияет: реализация выбрана по качественным основаниям, а
разброс `modernc` принят как риск, не ослабляющий бюджет (раздел 12 ADR).

### 2.6 Кроссплатформенность кода spike

- `syscall` и `golang.org/x/sys` только в файлах за build tags; ветвлений по
  `runtime.GOOS` в логике нет; хардкода разделителя пути нет.
- Найден пробел: `CollectMachineInfo` существовал только для darwin, linux и windows,
  и сборка под другой GOOS падала на общем файле. Добавлен вариант с тегом
  `!darwin && !linux && !windows`, `GOOS=freebsd` собирается.
- Сведения о машине на Windows берутся из реестра (`RegGetValueW`) и Win32 API, без
  `wmic`.

### 3.2 Бюджеты раздела 28 (не пересматриваются)

| Бюджет | Цель | Факт (modernc, `ut`) | Вердикт |
|---|---|---|---|
| cold full indexing | < 90 с | 95.1 с | **не выдержан** |
| инкремент одного BSL | < 300 мс | 492-567 мс | **не выдержан** |
| p50/p95 чтения | см. 4.4 ADR | доли миллисекунды | с запасом |
| размер индекса, относительно корпуса | < 2x объёма BSL+XML | 1.58x | выдержан |
| размер индекса, абсолютно | сотни МБ, не ГБ | 1 817.0 МБ | **не выдержан** |
| peak RSS при индексации | < 1.5 ГБ | 0.62 ГБ (без парсера) | выдержан, парсера здесь нет |

Три невыдержанных бюджета приняты как **risk signal**. Сами цели сохраняются:
targeted reconciliation обязательна в фазе 3, решение о материализации `call_edge`
отложено до фаз 5-6, путь к cold build лежит через фазу вставки ссылок, а не через
смену драйвера.

Оговорка: счётчики фактов смоделированы, а affected set инкремента раздут коллизиями
синтетических ключей (раздел 12 ADR), то есть цена инкремента здесь **завышена**.

## 5. Что НЕ проверено

1. **Windows runtime.** Прогон не выполнялся: Windows-машины не было. На macOS
   нельзя проверить даже синтаксис PowerShell (`pwsh` не установлен). Заявляется
   compile validated, не более; гейт описан в разделе 13.2 ADR.
2. **Счётчики фактов смоделированы**, а не получены парсером.
3. **Affected set раздут** коллизиями синтетических ключей.
4. **Одна машина, одна ОС, один диск** (APFS).
5. **Одна выгрузка**: демо-база УТ.
6. **Пул читателей не мерился под нагрузкой полного объёма**: его свойства
   проверены тестами, но прогоны раздела 4.5 ADR идут без аренды.
7. **Файловый кеш ОС не контролировался**, поэтому слово «холодный старт» к
   числам не применяется.
8. **Контролируемого сравнения реализаций по скорости нет**, см. 2.5.
