# ADR-39. HTTP-связи между базами: факты в индексе, сшивка при чтении

## Контекст

Issue #6, веха В2 (`docs/architecture-graph.md` §11, решение D10). При обменах одна база
вызывает HTTP-сервис другой, и эта связь нигде не видна: по коду вызывающей базы непонятно,
какой сервис и какой обработчик на той стороне затронуты. Карта и `object_graph` видят одну
базу.

Ограничения, которые определили решение:

- индексы баз независимые файлы SQLite (§11, D8): у каждой базы своё пространство id узлов, и
  внешний ключ из `object_data_edge` одной базы на `metadata_object` другой невозможен;
- маппинг хостов на проекты меняется чаще кода (новый стенд, переезд сервера), и правка
  маппинга не должна стоить полной пересборки индекса выгрузки на 50 тыс. файлов;
- в реальном коде (ut_demo, 85 модулей с `Новый HTTPСоединение`) адрес почти всегда
  вычисляется: сервер из настроек, путь из структуры URI. Сшивка обязана честно отличать
  «не нашли» от «не знаем» (D7);
- ADR-037/038: каждая новая таблица с внешними ключами на узлы других файлов обязана попасть
  в снимок указателей или каскадов при переопубликации, иначе инкремент молча теряет строки.

## Решение

**Факты в индексе своей базы, сшивка при чтении через границу индексов.**

1. Парсеры (`ParserVersion` 5):
   - `parse/bsl` даёт `Module.HTTPCalls`: вызов метода соединения (`Получить`, `Записать`,
     `ОтправитьДляОбработки`, `Изменить`, `Удалить`, `ПолучитьЗаголовки`, `ВызватьHTTPМетод`
     и `...Асинх`, английские синонимы) внутри метода, если соединение создано
     `Новый HTTPСоединение(...)` в этом же методе или запрос известен. Сервер берётся из
     литерала конструктора, путь из `Новый HTTPЗапрос(...)` или `Запрос.АдресРесурса = ...`:
     литерал (`static`), склейка со статическим началом или `СтрШаблон` (`prefix`, вместе
     со статическим концом после вычисляемой части: `"/base/hs/svc/" + Версия +
     "/GetIBParameters"`), строковая переменная метода; иначе путь `dynamic`. Привязки локальны методу, как у
     наборов записей регистра. Факт эвристический, confidence 0.85;
   - `parse/meta` даёт `Facts.HTTPService`: `RootURL`, шаблоны URL и методы с
     обработчиками. `RootURL` остаётся и в свойствах объекта.
2. Индекс (схема 5, шаг миграции создаёт таблицы и требует полной пересборки):
   - `http_endpoint`: строка на метод шаблона (шаблон без методов одной строкой с пустым
     методом), `file_id` XML сервиса. Объект-сервис не хранится ссылкой: это
     `metadata_object` того же `file_id`, чтение находит его соединением;
   - `http_call`: вызов с сервером, путём, видом пути, HTTP-методом и местом, `file_id`
     модуля и `symbol_id` метода. Обе таблицы держатся только за свой файл
     (`http_call.symbol_id` в `sameFileCascades`), в снимок ADR-037/038 им попадать нечего.
3. Сшивка (`resolve.StitchHTTPCall`, чистые правила):
   - путь `dynamic` ребра не даёт никогда: у объекта-владельца бейдж `has-dynamic-http` со
     счётчиком и местами вызова (D7, отдельное имя, чтобы не складываться с `has-dynamic`
     регистров);
   - литеральный сервер сопоставляется маппингу хостов workspace. Немапленный хост внешний
     (`host-unmapped`) даже при совпадающем пути: это сторонний сервис. Мапленный ищет сервис
     по пути только в своём проекте; не нашёл, значит тоже внешний (`no-endpoint`), проект
     не открыт (`project-not-loaded`);
   - вычисляемый сервер при известном пути ищет сервис во всех переданных проектах
     (`path-only`);
   - путь сопоставляется так, как платформа публикует сервис:
     `/<публикация>/hs/<RootURL><Template>`, `{Параметр}` занимает один сегмент, `*` забирает
     остаток, известное начало пути (`prefix`) совпадает с шаблоном, если корень известен
     целиком, а статический конец сужает шаблоны до тех, что им кончаются (вычисляемая часть
     между ними считается непустой); HTTP-метод фильтрует методы шаблона (`ANY` принимает любой). Совпал путь, но не
     метод: связь остаётся с причиной `verb-not-allowed`;
   - достоверность ниже 1 всегда: мапленный хост 0.9 (начало пути 0.7), только путь 0.6
     (0.5), итог связи не выше достоверности атрибуции.
4. Атрибуция (`resolve.AttributeSymbolFact`): вызов приписывается объекту тем же обходом
   вверх по статическому графу вызовов, что и запись в регистр (D6): общий модуль сквозной,
   достоверность минимум по цепочке, пороги штрафуют. Цепочка не дошла до объекта (общий
   модуль обмена, который зовёт регламентное задание): концом связи становится сам модуль
   вызова, место вызова помечено `attributed=false`.
5. Маппинг хостов: `<workspace>/.mcp1c/http-hosts.json`, рядом с реестром и индексами:
   `{"version":1,"hosts":[{"host":"erp.example.local","project":"erp"},{"host":"*.shop.local","project":"shop"}]}`.
   Хост без схемы, порта и пути, без учёта регистра, `*.` совпадает с поддоменами, точное
   правило сильнее шаблона. Нет файла: пустой маппинг. Сломанный файл: предупреждение
   `http_hosts_invalid` в ответе, не молчаливый пустой маппинг. Файл читается на каждый
   запрос.
6. Выдача: вид связи `http-call`, но **не в `object_data_edge`**. Связь адресует концы парой
   «проект, id строки его индекса» (`HTTPNodeRef`), внешняя связь без конца с
   `externalHost`:
   - `GET /api/crosslinks?projects=a,b` graph-режима: без `projects` все открытые
     `--project`; маппинги их workspace сливаются, расхождение идёт предупреждением
     `http_hosts_conflict`;
   - `object_graph`: `crossProjects=[корни]` или `kinds=[http-call]` добавляют блок
     `httpLinks` со связями и бейджами этого объекта (вызывающего или сервиса); прежний
     ответ без них не меняется;
   - `--project <workspace>#<id>` открывает конкретный проект реестра
     (`Projects.UseProject`, без записи `registry.json`): две базы одного workspace на одной
     карте.

## Отвергнутые варианты

- **Ребро `http-call` в `object_data_edge` на стадии публикации.** Конец ребра лежит в
  индексе другой базы, внешнего ключа на него нет. Ребро к локальной заглушке-узлу требовало
  бы синтетических `metadata_object`, их identity и места в снимках ADR-037/038, а сшивка на
  публикации привязала бы результат к маппингу хостов на момент индексации: правка маппинга
  стоила бы полной пересборки. Цена отказа: `neighbors`, `radius` и god-node по
  `object_data_edge` HTTP-связей не видят, их показывает отдельный слой карты.
- **Атрибуция при публикации в отдельной таблице владельцев вызова.** Ещё одна производная
  таблица с внешними ключами на `metadata_object` и инкрементальным пересчётом по сиду
  графа вызовов (как у `object_data_edge`). Вызовов HTTP на базу сотни, а не миллионы:
  обход при чтении дешевле ещё одного пути инкремента.
- **Сшивка неизвестного хоста по пути.** Даёт ложные рёбра к своим сервисам от вызовов
  сторонних API с совпадающим путём; «внешний HTTP» честнее и сам по себе сигнал про дыру в
  маппинге.

## Последствия

- `ParserVersion` 5 и схема 5: **полная пересборка индекса каждого проекта** после
  обновления сервера (миграция ставит `needs_full_rebuild`).
- Ответ `crosslinks` строится на каждый запрос: чтение фактов проекта и обход графа вызовов
  от каждого вызова. Проверка на двух копиях ut_demo (20.09.2026): `/api/crosslinks` по двум
  базам 2.8 с, `object_graph` с `crossProjects` 4.8 с первым вызовом (открытие индексов) и
  0.3...0.5 с следующими; 48 связей (одна сшитая синтетическая, 47 внешних), 81 место вызова,
  бейдж `has-dynamic-http` у 776 объектов: вызовы с вычисляемым адресом в общих модулях-хабах
  приписываются всем их вызывающим. Потолки обхода те же, что у атрибуции регистров, упор
  идёт предупреждением `http_attribution_truncated` (14 вызовов на базу).
- упрощение: вызов распознаётся, только когда соединение или запрос созданы в том же
  методе. Запрос, собранный в одной процедуре и отправленный в другой, в индекс не попадает
  вовсе (ни ребра, ни бейджа). Потолок: связи обменов, где отправка вынесена в общий
  помощник с параметром-запросом. Путь выше: межпроцедурная привязка переменных через
  параметры вызова (граф вызовов уже есть).
- упрощение: путь публикации (`/<публикация>/`) не сверяется, совпадение ищется от сегмента
  `hs`. Две публикации одной базы с одинаковым RootURL неразличимы, и это верно: это одна
  база. Путь выше: имя публикации в маппинге хостов.
- Карта рисует HTTP-связи отдельным слоем по кнопке: узел другой базы не раскрывается на
  карте текущего проекта, для этого нужно переключить проект.
