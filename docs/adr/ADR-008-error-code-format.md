# ADR-8. Код ошибки: текст в фиксированной позиции, не JSON-поле

## Контекст

Спецификация требует структурированные ответы и actionable errors:
машиночитаемый код ошибки как отдельное поле, наравне со структурными
успешными ответами (`structuredContent` по `outputSchema`).

## Решение

`go-sdk@v1.6.1` маршалит `Out` в `structuredContent` только на success-пути:
`toolForErr`/`SetError` строят `CallToolResult` из текста ошибки,
структурного поля там нет. Поэтому ошибка отдаётся текстом фиксированного
формата `[code] message (подсказка: hint) [проект, generation]`: агент
выделяет код текстовым разбором начала строки, а не JSON-парсингом.

## Почему

Форкать или обходить `go-sdk`, чтобы протащить структурное поле `code` в
error-путь, несоразмерно ограничению одной библиотеки: это добавило бы
второй, самодельный протокольный путь поверх официального SDK (тот же класс
риска, что и второй парсер в ADR-004). Ограничение действовало для всех 43
существовавших инструментов и раньше; оно стало видимым, только когда
спецификация явно потребовала машиночитаемый код.

## Последствия

Код ошибки передаётся текстом в фиксированной позиции, а не JSON-полем;
это принято как ограничение SDK и задокументировано один раз, чтобы новые
инструменты не решали этот вопрос заново. Апгрейд `go-sdk`, если он даст
структурные ошибки на error-пути, потребует пересмотра формата и, вероятно,
изменит контракт для клиентов, уже научившихся парсить текст по этой схеме.
