# Коннектор живой базы (read-only HTTP-сервис)

Расширение конфигурации (`.cfe`) с HTTP-сервисом, через который Go-клиент
`HTTPSource` (`internal/source/httpsource.go`) читает живую базу. **Строго
read-only**: только чтение метаданных, SELECT-запросы и журнал регистрации;
эндпоинтов записи и выполнения произвольного кода нет.

Модуль сервиса: [`src/HTTPServices/MCP_Сервис/Ext/Module.bsl`](src/HTTPServices/MCP_Сервис/Ext/Module.bsl)
— проверен BSL language server (0 errors, 0 warnings) и прогнан на живой базе УТ 11.5.22
через автономный сервер; регрессионный контур — `internal/source/live_integration_test.go`
(запускается только при заданном `MCP_1C_BASE_URL`).

## HTTP-контракт

Базовый URL коннектора (значение флага `--base`): `http://<хост>/<база>/hs/mcp-1c`.

Два расширения с одним корневым URL в одной базе конфликтуют: если в базе уже есть другое
расширение с корневым URL `mcp-1c`, его надо снять.

| Метод | URL | Обработчик | Ответ (Go-тип) |
|---|---|---|---|
| GET | `/configuration` | `КонфигурацияGET` | `ConfigurationInfo` |
| GET | `/metadata` | `МетаданныеGET` | `MetadataTree` |
| GET | `/object/{type}/{name}` | `ОбъектGET` | `ObjectStructure` |
| POST | `/query` `{query,parameters,limit,timeout,refs}` | `ЗапросPOST` | `QueryResult` |
| POST | `/validate-query` `{query}` | `ВалидацияЗапросаPOST` | `ValidateResult` |
| POST | `/eventlog` `{start_date,end_date,level,user,limit}` | `ЖурналPOST` | `EventLogResult` |
| GET | `/subsystem/{name}` | `ПодсистемаGET` | `SubsystemInfo` |
| GET | `/predefined/{type}/{name}` | `ПредопределенныеGET` | `PredefinedList` |

Авторизация — штатная базы (HTTP Basic); клиент передаёт `--user`/`--password`.

### Ошибки

По умолчанию ошибка уходит кодом HTTP и текстом в теле. Веб-сервер перед 1С (IIS) такое тело
подменяет своей страницей, и до клиента доходит только «Неправильный запрос». Поэтому клиент,
который умеет читать конверт, шлёт заголовок `X-MCP-Errors: envelope` и получает ошибку с
кодом 200:

```json
{"error": {"status": 400, "code": "query_failed", "message": "Ошибка выполнения запроса: …"}}
```

Коды: `bad_request`, `forbidden`, `not_found`, `query_failed`, `read_failed`, `internal_error`.
Go-клиент разбирает конверт в `HTTPSource.do` и отдаёт `ConnectorError`. Непредвиденное
исключение в обработчике перехватывается на границе сервиса: клиенту уходит краткий текст
(`internal_error`), подробности со стеком пишутся в журнал регистрации базы событием
«MCPКоннектор.Ошибка обработки запроса». Других записей в базу коннектор не делает.

### Запрос: время, параметры, ссылки

Запросы выполняет общий модуль `MCP_Запросы`
([`src/CommonModules/MCP_Запросы/Ext/Module.bsl`](src/CommonModules/MCP_Запросы/Ext/Module.bsl)).

- **`timeout`** (секунды, не больше 240). Запрос, который идёт дольше, прерывается в базе, ответ:
  ошибка `query_timeout` (статус 408). Запрос нельзя прервать из вызова, который его выполняет,
  поэтому при заданном `timeout` он уходит в фоновое задание (`MCP_Запросы.ВыполнитьВФоне`),
  сервис ждёт его `ОжидатьЗавершенияВыполнения` и отменяет. Без `timeout` и в монопольном
  режиме запрос идёт в самом вызове, без ограничения. Go-клиент шлёт `timeout` всегда: флаг
  `--query-timeout`, переменная `MCP_1C_QUERY_TIMEOUT`, по умолчанию 30 с, `0` выключает.
- **`parameters`**. JSON не знает дат и ссылок, поэтому значения приводятся: строка
  `2026-09-01` или `2026-09-01T00:00:00` становится датой, объект `{"type", "ref"}` ссылкой,
  `{"type", "value"}` значением перечисления, массив обрабатывается поэлементно. Строка
  другой формы остаётся строкой. Непонятный объект, неизвестный тип и дата вида `2026-13-45`
  дают ошибку 400 с именем параметра.
- **`refs: true`**. Ссылка в строке результата уходит объектом
  `{"presentation", "type", "ref"}`, значение перечисления объектом
  `{"presentation", "type", "value"}`. Тот же объект принимается в `parameters`. Без `refs`
  ссылка уходит строкой-представлением, как раньше.
- В ответе есть `duration_ms`: сколько запрос шёл в базе вместе с подготовкой ответа.

## Гарантии read-only

- Фоновое задание запроса с ограничением времени выполняет тот же `Запрос.Выполнить()` тем же
  пользователем и ничего не пишет; результат передаётся через временное хранилище сеанса.
- `/query` выполняет `Запрос.Выполнить()` только для текста, начинающегося с
  `ВЫБРАТЬ`/`SELECT` (проверка `ЭтоSelect`); не-SELECT → HTTP 403. Язык запросов 1С
  сам по себе не имеет операций записи.
- `/validate-query` использует `Запрос.НайтиПараметры()` — парсинг без выполнения.
- Нигде не используется `Выполнить()`/`Вычислить()` над пользовательским вводом.
- SELECT-guard продублирован на стороне Go-клиента (`ensureSelect`).

## Как собрать `.cfe` и опубликовать

1. **Создать расширение.** Версию формата выгрузки бери из свежей выгрузки той конфигурации,
   куда пойдёт расширение: она зависит от версии платформы, а не от режима совместимости.
   Например, платформа 8.3.27.2130 грузит только `2.20` и на `2.21` падает с «Неизвестная
   версия формата». Готовые исходники лежат в `src/`, пересобрать XML-описание под свою
   выгрузку можно так: `python3 tools/build_src.py --from-dump <каталог выгрузки>`.
2. **Добавить объект `HTTPСервис`** с именем `MCP_Сервис`, корневой URL `mcp-1c`.
3. **Шаблоны URL и методы** (каждый шаблон → метод → функция-обработчик модуля):

   | Шаблон | Адрес | HTTP-метод | Обработчик |
   |---|---|---|---|
   | `configuration` | `/configuration` | GET | `КонфигурацияGET` |
   | `metadata` | `/metadata` | GET | `МетаданныеGET` |
   | `object` | `/object/{type}/{name}` | GET | `ОбъектGET` |
   | `query` | `/query` | POST | `ЗапросPOST` |
   | `validatequery` | `/validate-query` | POST | `ВалидацияЗапросаPOST` |
   | `eventlog` | `/eventlog` | POST | `ЖурналPOST` |
   | `subsystem` | `/subsystem/{name}` | GET | `ПодсистемаGET` |
   | `predefined` | `/predefined/{type}/{name}` | GET | `ПредопределенныеGET` |

4. **Модуль HTTP-сервиса** = содержимое `src/HTTPServices/MCP_Сервис/Ext/Module.bsl`.
   **Общий модуль `MCP_Запросы`** (серверный: «Сервер», «Внешнее соединение», «Клиент (обычное
   приложение)») = содержимое `src/CommonModules/MCP_Запросы/Ext/Module.bsl`.
5. **Загрузить расширение** в тестовую базу (не прод).
6. **Опубликовать базу**: на Windows/Linux через веб-сервер (Apache/IIS), на macOS
   через автономный сервер `ibsrv` — там HTTP-сервисы перечисляются в yaml поимённо,
   иначе `/hs/...` отдаёт 503.
7. **Собрать `.cfe`** (по желанию): загрузить `src` в тестовую базу конфигуратором
   (`/LoadConfigFromFiles src -Extension "MCPКоннектор"`) и выгрузить файл расширения
   (`/DumpCfg <файл>.cfe -Extension "MCPКоннектор"`). Готовый `.cfe` в репозитории не
   хранится: он привязан к версии платформы, на которой собран.
8. **Запустить сервер** в live-режиме:
   `mcp1c --base http://<хост>/<база>/hs/mcp-1c --user <U> --password <P>`

## Ограничения и потолки

- **`FormStructure` и `SearchCode` в live не поддержаны**: дерево элементов управляемой
  формы и тексты модулей во время исполнения недоступны. Эндпоинтов для них нет,
  Go-клиент отдаёт по ним ошибку сам и отправляет в оффлайн-режим (`--dump`).
- **`analyze_query` эндпоинта не имеет**: анти-паттерны считаются по тексту запроса на
  стороне Go тем же анализатором, что и оффлайновый `query_advisor`. Проверки на
  неиндексируемые отборы остаются оффлайновыми: признак `Indexing` есть только в XML.
- **Потолки коннектора** (клиент может просить меньше, больше нет): `/query` 1000 строк,
  `/eventlog` 500 записей, `/predefined` 1000 элементов. Везде читается на запись больше
  потолка, и обрезка отдаётся флагом `truncated`, а не угадывается клиентом. Для журнала
  ограничение передаётся в саму `ВыгрузитьЖурналРегистрации`, иначе многолетний журнал уедет
  в память рабочего процесса ради пяти строк ответа.
- **Отбор журнала строгий**: `level` принимается и по-русски (`Ошибка`), и по-английски
  (`Error`), `user` — это имя пользователя ИБ, коннектор разрешает его в идентификатор через
  `ПользователиИнформационнойБазы.НайтиПоИмени`. Неизвестный пользователь, нераспознанный
  уровень и неразбираемая дата дают HTTP 400. Молча снятый отбор хуже ошибки: клиент получил
  бы выборку шире запрошенной и принял её за отфильтрованную.
- **`/predefined` читает данные**: представление ссылки берётся `ПредопределенноеЗначение`.
  Элемент, описанный в метаданных, но отсутствующий в базе, отдаётся с пустым `ref`.
- Типы реквизитов в `/object` отдаются полными именами (`НайтиПоТипу(...).ПолноеИмя()`),
  формат может слегка отличаться от оффлайновой русификации.
